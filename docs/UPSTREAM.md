# Upstream findings

Engine behaviors discovered while building blitz-py. First found against `blitz 0.3.0-beta.1` / `fontique 0.10` / `vello_cpu 0.0.9`; last re-checked 2026-10-28 against `blitz 0.3.0-beta.4` (crates.io) / `parley`+`fontique 0.12` / `anyrender 0.14` / `anyrender_vello_cpu 0.18`. Kept here as the source of truth for our workarounds; revisit on every dependency bump.

| Finding | Where | Our workaround | Status upstream |
|---|---|---|---|
| `parley::FontContext::new()` leaks ~115KB per call (platform font scan) and costs ~25ms | fontique 0.10, still present in 0.12 (re-measured with `examples/leak.rs`) | Build the font collection once, clone per render (`base_collection()`) | Not reported (repro: `examples/leak.rs`, stages `fontctx` vs `paint`) |
| Without a `base_url`, the document base is a `data:` URL, which cannot anchor relative URLs; `resolve_url` then panics on `<img src="logo.png">`, `<link href="a.css">`, `<iframe src>`, `//host/x` | blitz-dom `DocumentUrl::default` + `BaseDocument::resolve_url` (`unwrap_or_else(panic!)`), beta.1 through beta.4 | Default to the hierarchical base `blitz-py:///`; reject non-hierarchical `base_url`s with `ValueError` | Not reported |
| Images are decoded in full with no pixel limit (`ImageReader::decode()` with the image crate's default 512MB allocation cap), so a few-KB PNG declaring 9000x9000 allocates ~400MB | blitz-dom `ImageHandler::parse`, beta.4 | `SyncProvider` sniffs the header and drops images over `MAX_PIXELS` | Not reported |
| Stylo leaks a per-thread bloom filter and style-sharing cache: `Box::leak` into TLS (`bloom.rs`, `sharing/mod.rs`, "we don't have the guarantee of TLS destructors to run in worker threads"), so every *new* thread that styles a document costs ~37KB forever (`examples/leak.rs` stage `thread_doc` vs `thread_noop`/`doc_shared`) | stylo 0.22 via blitz-dom beta.4 | Render on reused pooled threads (`with_render_stack`); a `Template` keeps one worker | By design upstream; spawning a thread per render was our bug (geekmagic-hacs#209, fixed in 0.6.0) |
| SVG `<text>` resolves fonts via usvg's own fontdb, not the document font collection — bundled/registered/`@font-face` fonts don't apply | blitz-paint / anyrender_svg, still in beta.4 | Avoid SVG text; overlay HTML text | Not reported |
| Bundled font family naming: fontique registers fonts under internal name (`"Inter Variable"`), so name-based defaults can silently bind to a system font or nothing | fontique | Register with `FontInfoOverride { family_name }` and wire generics by `FamilyId` | Working as designed; gotcha documented |
| `@font-face` sources with no `format()` hint and no URL file extension were silently skipped (data: URIs) | blitz-dom `fetch_font_face`, beta.1 | — | **Fixed** by beta.4 (format-less `data:font/ttf` URIs load) |
| CSS *animations* didn't apply to `<svg>` elements (static transforms did) | blitz-dom style/animation, beta.1 | — | **Fixed** by beta.4 |
| `DocumentMutator::set_style_property` didn't invalidate layout | blitz-dom 0.3.0-beta.1 | `Template.set_style` rewrites the `style` attribute instead (kept — equally correct, and no need to churn) | **Fixed** (#582) |
| System-font scan panicked when fontconfig is installed but zero fonts are (`font_sort(...).unwrap()` on `NoMatch`) — hit on fresh Home Assistant base images | fontique ≤ 0.11.1 `backend/fontconfig.rs` | Was: probe under `catch_unwind`. Dropped in 0.6.0; the `fontless-test` CI job remains as the regression test | **Fixed** in fontique 0.12 (`let Ok(..) else` skip) |
| `anyrender` failed to compile on 32-bit targets (`size_of::<FilterEffect>()` assertion assumed 64-bit pointers) | anyrender ≤ 0.13 | Was: no armv7 wheels | **Fixed** in anyrender 0.14 (per-pointer-width assertion) |

Worth contributing upstream when we engage: `text-overflow: ellipsis` support in blitz-dom (open as DioxusLabs/blitz#1015) — consumers re-implement truncation in application code; `ellipsize`/`line_clamp` remove the metric-mismatch pain but native ellipsis is the real fix. `text-shadow` rendering is likewise open (#984).

Also relevant but not engine bugs:

- The `anyrender` / `anyrender_vello_cpu` / `parley` versions must match the blitz release's workspace `Cargo.toml`: beta.1 needed `anyrender 0.11` + `anyrender_vello_cpu 0.14`; beta.4 needs `anyrender 0.14` + `anyrender_vello_cpu 0.18` + `parley 0.12`. Re-pair on every bump. The blitz crates are exact-pinned (`=0.3.0-beta.4`) because a caret range on a prerelease admits the next beta with mismatched pairings.
- We build blitz-dom with `default-features = false` (dropping accessibility, file-input and custom-widget code), so every default feature we do want must be listed: `woff` (WOFF/WOFF2 `@font-face`) is enabled since 0.6.0 — before that, WOFF fonts silently fell back to the default face. `svg` arrives via blitz-paint.
- CSS floats are behind blitz-dom's opt-in `floats` feature (not in upstream's defaults either), which we do not enable: `float: left/right` boxes lay out as ordinary blocks.
- Parley 0.12 pixel-snaps line heights (`normal` for 16px Inter: 19.36 → 20px), shifting text by ≤1px vs 0.5.0 and changing `measure_text` heights accordingly.
